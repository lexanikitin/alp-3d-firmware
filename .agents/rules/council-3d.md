# Золотая Коллегия моделей OpenRouter (Alpaca 3D Lab — OrcaSlicer & Klipper Fleet)

В проекте **Alpaca 3D Lab** базовую разработку, чтение/редактирование файлов, запуск скриптов фермы и рутину ведет **Gemini 3.8 Flash** (бесплатно в рамках подписки).

Для задач физики экструзии, калибровки филаментов, настройки кинематики Voron 2.4 / Ender-3, написания G-code макросов Klipper, разбора сбоев печати и архитектурного аудита флота Агент (Gemini) привлекает профильных специалистов OpenRouter через инструмент MCP `openrouter/send-message`.

## 2. Коллегиальные режимы вызова

### 👥 `@council` / «Совет» (Адаптивный Совет 3D-фермы — 3 эксперта)
**Триггеры вызова**:
- Прямой запрос пользователя со словом **«Совет»** (в любом регистре: «Совет», «совет», «спроси совет», «что скажет совет»).
- Командный тег **`@council`**.

При вызове Gemini анализирует задачу и автоматически собирает профильную тройку через MCP `openrouter/send-message`:
1. **🧪 Калибровка пластика и профилей (NIT PETG, PETG-CF, ABS, TPU и др.)**:
   ➔ **`@slicer`** *(расчет расхода, PA, ретрактов)* + **`@r1`** *(усадка, адгезия, засоры)* + **`@taste`** *(швы, гладкость слоев)*.
2. **🏎️ Кинематика, ускорения и скоростная печать (Voron vs Ender)**:
   ➔ **`@slicer`** *(ускорения, ограничения экструдера)* + **`@klipper`** *(Input Shaping, Jinja2)* + **`@r1`** *(риски пропуска шагов)*.
3. **🛠️ Автоматизация фермы и скрипты (`farm_sync.py`, Moonraker API, YAML)**:
   ➔ **`@architect`** *(модульность и надежность)* + **`@klipper`** *(код Python / API)* + **`@r1`** *(обрывы сети, целостность бэкапов)*.
4. **🧯 Разбор брака, дефектов и аварийных остановов печати**:
   ➔ **`@r1`** *(первопричина сбоя)* + **`@klipper`** *(анализ логов и G-code)* + **`@taste`** *(корректировка геометрии печати)*.

---

### ⚖️ `@tribunal` (Верховный Трибунал 3D-Фермы — 5 экспертов)
Вызывается перед отправкой новых базовых профилей на весь парк или обновлением общих G-code макросов для всех 7 принтеров:
Состав: **`@r1`** + **`@slicer`** + **`@architect`** + **`@klipper`** + **`@iot`**.
Gemini сводит вердикты в итоговую матрицу: Риски сбоев печати, Физика расхода, Архитектура профилей, Макросы Klipper, Аппаратные риски.

## 3. Регламент вывода для Gemini

1. При одиночном `@алиас` — вывести ответ модели с плашкой:
   > 🤖 **Ответ эксперта [`model_name`]** *(OpenRouter)*:
2. При `@council` / **«Совет»** или `@tribunal`:
   - Gemini собирает ответы экспертов, устраняет повторения и представляет **Сводную таблицу консенсуса и рисков** (или структурированные тезисы каждого эксперта + итоговый синтез).
   - **ОБЯЗАТЕЛЬНЫЙ ОТЧЕТ В КОНЦЕ КАЖДОГО ВЫЗОВА СОВЕТА (Биллинг и Баланс)**:
     После каждого вызова Совета Gemini обязан запросить `openrouter/get-credits` и вывести в самом конце ответа обязательный блок:
     ```markdown
     ---
     📊 **Отчет работы Совета**:
     - **Использованные модели**: `[модель 1]`, `[модель 2]`, `[модель 3]`
     - **Потрачено токенов / стоимость**: ~X input, ~Y output (~$0.00Z)
     - **Текущий баланс OpenRouter**: $X.XX (доступно)
     ```
